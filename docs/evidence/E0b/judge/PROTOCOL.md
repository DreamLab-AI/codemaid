# E0b endpoint 4 judging protocol

Generated by `e0 run-b`. Do not edit.

The sample is drawn only from (commit, topic) pairs flagged by T_file but not T_region whose commit comes after the topic's stamp in that repository (the stamp is an ancestor of, or is, the commit's parent), so the topic text predates the change it is judged against.

1. Each `<id>.prompt.md` is given, unchanged, to a fresh Claude subagent with no other context. Its reply (one JSON object) is saved as `<id>.j1.json`.
2. Every pair whose first verdict is `yes` is given, unchanged, to a second fresh subagent, independent of the first (it does not see the first verdict). Its reply is saved as `<id>.j2.json`.
3. A pair is a **hidden real change** when both judges answer `yes`. A first `yes` the second judge does not confirm counts as not hidden.
4. `e0 score --out docs/evidence/E0b` computes the hidden-real-change rate per stratum and pooled, with the Wilson 95% upper bound, and writes `endpoint4.json` and `ENDPOINT4.md`. **Success:** pooled rate ≤ 10%. With fewer than 20 eligible pairs in total the endpoint is reported as UNDERPOWERED, not passed.

The judge must not be the context that drew the sample or wrote the harness. `line_anchors_only` is recorded so a reader can see how many `yes` verdicts rest only on moved line anchors; it does not change the pre-registered scoring.
